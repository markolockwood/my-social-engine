## [1.7.0] - 2026-08-07

### Новые возможности

#### Пагинация с бесконечной прокруткой
- **Пагинация постов на главной странице**:
  - Первая загрузка: 25 постов
  - Подгрузка при скролле: по 15 постов
  - Автоматическая загрузка через Intersection Observer
  - Индикатор "Больше постов нет" в конце ленты
- **Пагинация комментариев**:
  - Первая загрузка: 15 комментариев
  - Подгрузка при скролле: по 10 комментариев
  - Работает на детальной странице поста и в лайтбоксе
  - Индикатор "Больше комментариев нет" в конце списка

#### Сортировка комментариев
- **Три типа сортировки**:
  - **Recent (Последние)** - по времени создания, новые сверху (по умолчанию)
  - **Relevant (Релевантные)** - по формуле: лайки × 2 + время
  - **Likes (По лайкам)** - по количеству лайков
- **Стилизованный dropdown** в стиле Twitter:
  - Кнопка показывает текущую сортировку: "Recent ›", "Relevant ›", "Likes ›"
  - Выпадающее меню с заголовком "Sort replies" / "Сортировка ответов"
  - Галочка у активного элемента
- **Сортировка без перезагрузки** страницы
- **Условное отображение**:
  - Dropdown сортировки показывается только если есть комментарии
  - "View quotes →" показывается только если есть быстрые ответы
- Работает на детальной странице поста и в лайтбоксе

#### Автообновление счетчиков при просмотре поста
- **Polling каждые 15 секунд** для одного открытого поста:
  - Обновление количества лайков
  - Обновление количества комментариев
  - Обновление количества просмотров
  - Синхронизация статуса лайка (is_liked)
- **Легкий SQL запрос** - только счетчики без JOIN и медиа
- Работает на детальной странице поста и в лайтбоксе
- **Нагрузка**: 500 одновременных пользователей = ~33 запроса/сек

#### Показ новых комментариев
- **Polling каждые 20 секунд** для проверки новых комментариев
- **Баннер** "Show N new replies" при появлении новых комментариев
- **Клик по баннеру** загружает и показывает свежие комментарии
- Работает на детальной странице поста и в лайтбоксе

#### Глобальная синхронизация данных постов (PostsContext)
- **Централизованное управление состоянием** всех постов в приложении
- **Синхронизация между компонентами**:
  - Лайк в MediaLightbox отображается в Post и наоборот
  - Счетчики комментариев обновляются везде одновременно
  - Изменения видны во всех компонентах, отображающих тот же пост
- **Автообновление времени постов** каждую минуту
- **Оптимистичные обновления** с откатом при ошибке
- API методы: `initPost()`, `updatePost()`, `toggleLike()`, `incrementComments()`, `incrementViews()`, `getPostState()`, `removePost()`

#### Улучшения лайтбокса
- **Блокировка скролла body** при открытом лайтбоксе
- **Видимый скроллбар** для комментариев в правой части
- Скролл страницы на фоне заблокирован, работает только для комментариев

### Backend

#### Новые API эндпоинты
- `GET /api/posts/{id}/counters` - получение только счетчиков поста (легкий запрос для polling)
- Поддержка `limit` и `offset` в `GET /api/posts/{id}/replies` для пагинации комментариев

#### Изменения в базе данных
- Добавлен счетчик `quick_replies_count` в базовый SELECT всех постов
- Подсчитывает количество быстрых ответов к посту: `SELECT COUNT(*) FROM posts WHERE parent_id = p.id AND is_quick_reply = true`

#### Логика вкладки "Посты" в профиле
- **Исправлена логика** отображения постов пользователя:
  - Показываются: оригинальные посты (`parent_id IS NULL`) + быстрые ответы (`is_quick_reply = true`)
  - Скрываются: обычные комментарии под чужими постами (они идут во вкладку "Ответы")
- Соответствует логике Twitter/X

### Улучшения

#### Система переводов
- **Поддержка параметров** в функции `t()`:
  - `t('post_page.show_new_replies', { count: 5 })` → "Show 5 new replies"
  - Замена всех `{{variable}}` на реальные значения
- Полная мультиязычность для всех новых функций (RU/EN)

#### Оптимизация производительности
- **Легкие SQL запросы** для polling - только необходимые поля
- **Минимальная нагрузка на БД** - один запрос на один открытый пост
- **Intersection Observer** вместо scroll events для пагинации

### Исправления

#### Критические баги
- **Посты не отображались на личной странице**: Запрос `getByUserId()` возвращал все посты включая обычные комментарии. Добавлен фильтр `AND (p.parent_id IS NULL OR p.is_quick_reply = true)`
- **Счетчики не обновлялись визуально**: Использовался `initPost()` вместо `updatePost()` в polling, что не вызывало ре-рендер. Исправлено на `updatePost()`

#### SQL исправления
- Изменено написание `TRUE/FALSE` на `true/false` в SQL запросах для единообразия (PostgreSQL)

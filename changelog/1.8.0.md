## [1.8.0] - 2026-08-08

### New Features

#### Smart Post View Counter
- **Session-based view deduplication** (Twitter-like logic):
  - A repeat view of the same post by the same user does not increase the counter within a 3-hour window
  - After the window expires, the next view is counted again
  - Works for both authenticated users (by user ID) and anonymous visitors (by IP)
  - The author viewing their own post is counted on the same basis as anyone else
- **View tracking in the feed**:
  - A post is counted as viewed once it has stayed in the viewport (≥50% visible) for at least 3 seconds
  - Implemented via `IntersectionObserver` inside the `Post` component
  - Fast scrolling does not count fleeting appearances as views
  - A view in the feed and a view on the post detail page are the same counted event, not two separate views
- **Client-side request deduplication**:
  - A view request for a given post is sent at most once per SPA session
  - The same post reappearing in the feed (after scrolling up/down) does not trigger extra network requests
  - Implemented via `markPostViewed()` in `PostsContext`

### Backend

#### Redis Integration
- Added **Redis** as a dependency — used for ephemeral data (view deduplication, and in the future presence/typing indicators for chat)
- New `RedisClient` class (`api/classes/Redis.php`) — singleton wrapper over php-redis, following the same pattern as `Database.php`
- New `redis` section in `config/config.php` (host, port, timeout)
- Graceful degradation: if Redis is unavailable, views are counted without deduplication (not lost), the app keeps working

#### API Changes
- `POST /api/posts/{id}/view` now returns `{ "counted": true|false }` instead of a static message — the frontend uses this to know whether the view was actually counted
- `RateLimitMiddleware::getClientIp()` made public for reuse when identifying anonymous views

### Bug Fixes

#### View Counter Desync
- **Fixed**: opening a post showed an inflated counter (+1) until the actual value arrived via `/counters` polling
- Cause: the frontend optimistically incremented the counter without accounting for server-side deduplication
- The local counter now only increments when the server responds with `counted: true`

## [1.8.2] - 2026-08-09

### Security

#### Critical Vulnerabilities Fixed (8 fixes)

**1. IP Spoofing in Rate Limiting**
- **Issue**: An attacker could forge the `X-Forwarded-For` header to bypass rate limiting by changing IP with each request
- Added whitelist of trusted proxies (localhost). X-Forwarded-For is only considered from trusted sources, with IP validation via `FILTER_VALIDATE_IP` and filtering of private addresses

**2. CSRF Protection**
- **Issue**: No protection against CSRF attacks. An attacker could create posts, delete content on behalf of the victim
- Created `CsrfMiddleware` with Origin/Referer header checking for all POST/PUT/PATCH/DELETE requests. For requests with JWT token, validation is relaxed (JWT in localStorage is already CSRF protection)

**3. Command Injection in FFmpeg**
- **Issue**: Using `exec()` with command string created command injection risk
- Rewrote `convertGifToMp4()` method using `proc_open()` with array of arguments instead of string. Hardcoded FFmpeg path or strict validation from config. Added input path validation via `realpath()` for path traversal protection

**4. User Enumeration via Error Messages**
- **Issue**: Detailed error messages (`"Username already exists"`, `"Email already exists"`) allowed checking username/email existence
- Generalized error messages: `"Username or email already exists"` → `"Registration failed. Please try different credentials"`, `"Username is already taken"` → `"Username change failed"`

**5. File Validation via Magic Bytes**
- **Issue**: Only checking MIME type via `finfo_file()` without validating actual file content
- Created `FileValidator` class with magic bytes checking methods (first bytes of file) for JPEG/PNG/GIF/WebP. Added validation via `getimagesize()` and magic signature verification
- Validation added to `uploadPostImages()`, `uploadPostGif()`, `uploadAvatar()` - files with invalid magic bytes are deleted with message "Invalid image file detected"

**6. Gender Validation with Whitelist**
- **Issue**: Free input up to 16 characters without content validation, injection possibility
- Added whitelist of allowed values: Male, Female, Non-binary, Other, Prefer not to say. Empty value allowed (optional field)

**7. GeoIP via API**
- **Issue**: Simplified IP prefix checking (only for Russian addresses), easy to bypass
- Integrated free API ip-api.com (45 requests/minute). Added 3-second timeout, IP validation with private address filtering, graceful fallback when API unavailable

**8. Cross-platform FFmpeg Process Termination**
- **Issue**: `pkill -f` only works on Linux, doesn't work on Windows
- Solution: 
  - Added DB migration to store process PID in `process_pid` column of `temp_uploads` table
  - When starting FFmpeg, PID is saved to DB
  - Created `killFFmpegProcess($pid)` method with OS detection (Windows: `taskkill /F /PID`, Linux: `kill -9`)
  - Updated `deleteMediaFile()` to use PID instead of pkill
  - Fallback: if no PID, uses old method

#### JWT Secret: Moved to .env
- Secret now read from `.env` (file in `.gitignore`, not committed to repository)
- Added instruction in README for generating cryptographically strong 256-bit secret
- `config.php` loads `.env` with fallback to placeholder if `.env` not created

#### CORS
- Header `Access-Control-Allow-Origin: *` replaced with whitelist of allowed origins from config (`CORS_ALLOWED_ORIGINS` in `.env`)
- Automatic localhost port allowance in development mode

#### Path Traversal
- Endpoint `DELETE /upload/media` now validates paths via `realpath()`: final path must be inside `/uploads`, otherwise 403
- Validation added for single files, HLS video directories, and previews

#### Access/Refresh Token System
Implemented standard two-token scheme:
- **Access token** — 15 minutes, passed in `Authorization` header with each request
- **Refresh token** — 30 days, stored in DB `refresh_tokens`, tied to user/IP/user-agent

**Benefits:**
- Stolen access token useless after 15 minutes
- Refresh token can be revoked via `logout-all`
- Token refresh transparent through axios interceptor

**Files**: `api/classes/JWT.php`, `api/controllers/AuthController.php`, `src/context/AuthContext.jsx`, `src/api/api.js`, `database/migrations/013_add_refresh_tokens.sql`

### Refactoring

#### Code Duplication Elimination (~190 lines removed)

**1. BaseController (30 lines saved)**
- Created abstract `BaseController` with common methods `getInput()`, `sendResponse()`, `sendError()`
- All controllers now inherit from base class: `class PostController extends BaseController`
- Removed 6 duplicate methods (3 × getInput + 3 × sendResponse) from AuthController, UserController, PostController
- **Files**: `api/controllers/BaseController.php` (new), all controllers

**2. TempUploadsHelper (110 lines saved)**
- Created helper for working with temporary uploads
- Methods: `checkLimitAndLock()`, `releaseLock()`, `register()`, `remove()`, `getAndRemove()`, `updateProcessPid()`
- Replaced 3 identical limit check blocks (~60 lines) in `uploadPostImages()`, `uploadPostGif()`, `uploadPostVideo()`
- Replaced 3 temp_uploads registration blocks (~45 lines)
- Simplified `cancelUpload()` and `deleteUploadedMedia()` methods using `getAndRemove()`
- **Files**: `api/helpers/TempUploadsHelper.php` (new), `api/controllers/PostController.php`

**3. FileUploadConfig (50 lines saved)**
- Created centralized configuration for file types
- Constants for MIME types, extensions, maximum sizes for: images, GIF, video, avatars
- Methods: `getAllowedMimes()`, `getAllowedExtensions()`, `getMaxSize()`, `getUploadDir()`, `generateFilename()`
- Replaced hardcoded constants in 4 upload methods with centralized configuration
- **Before**: `$allowedTypes = ['image/jpeg', 'image/png', 'image/webp']; $maxSize = 5 * 1024 * 1024;`
- **After**: `$allowedTypes = FileUploadConfig::getAllowedMimes('image'); $maxSize = FileUploadConfig::getMaxSize('image');`
- **Files**: `api/config/FileUploadConfig.php` (new), controllers

**4. Frontend Component Restructuring by Features**
- Components regrouped by domains:
  - `components/compose/` — ComposePost, ComposeWidget, ComposeReplyModal, MediaUpload
  - `components/post/` — Post, QuotedPost, PostMedia, RepliesSortDropdown, VideoPlayer, MediaLightbox
  - `components/user/` — UserCard, UserLink, UserHoverCard, EditProfileModal
  - `components/layout/` — Layout, Sidebar, MobileNav, GlobalUploadIndicator
- Settings pages moved to `pages/settings/`
- CSS files colocated with corresponding `.jsx`
- Added alias `@` → `src/` in `vite.config.js`
- Removed dead code: `ImageLightbox.jsx`, orphaned `Compose.css`
- `ChangeUsername.css` renamed to `ChangeForm.css` (common style for 4 forms)

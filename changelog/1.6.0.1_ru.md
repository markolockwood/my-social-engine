## [1.6.0.1] - 2026-08-06

### Новые возможности

#### Синхронизация медиа между вкладками
- **Прикрепление медиа синхронизируется**: При прикреплении изображения/видео/GIF в одной вкладке, оно автоматически появляется во всех открытых вкладках главной страницы
- **Удаление медиа синхронизируется**: При откреплении медиа в одной вкладке, оно исчезает из всех вкладок
- **Восстановление после перезагрузки**: Прикреплённые медиа восстанавливаются из БД (`temp_uploads`) при открытии новой вкладки или обновлении страницы
- **Синхронизация черновиков**: При публикации поста в одной вкладке, текст черновика и медиа очищаются во всех открытых вкладках
- Использует `BroadcastChannel API` для межвкладочной коммуникации

#### Система временных загрузок (temp_uploads)
- **Таблица temp_uploads** для хранения временно загруженных медиа перед публикацией поста, отказались от localStorage браузера (там хранится только текст) 
- **TTL 6 часов**: Автоматическая очистка неиспользованных медиа через 6 часов (cronjob) вместо 48
- **API эндпоинты**:
  - `GET /api/temp-uploads` - получение списка загруженных медиа текущего пользователя
  - `DELETE /api/upload/media` - удаление медиа с проверкой владельца
  - `POST /api/upload/cancel` - отмена загрузки по tracking ID
- **Лимит 4 медиа**: Ограничение количества одновременно прикреплённых файлов для предотвращения злоупотреблений
- **Tracking ID**: Уникальный идентификатор для каждой загрузки (позволяет отменить загрузку видео во время конвертации)

#### Контексты загрузки
- **Главная страница** (`compose_main`): Медиа сохраняется в `temp_uploads`, восстанавливается при перезагрузке
- **Комментарии** (`comment_{postId}`): Медиа НЕ сохраняется в БД, удаляется при unmount компонента
- Заголовок `X-Upload-Context` определяет поведение загрузки

### Безопасность

#### Исправлены race conditions
- **Race condition при создании постов**: Использован атомарный `DELETE...RETURNING` в `Post::create()` для предотвращения дублирования медиа в нескольких постах
- **Race condition в лимите 4 медиа**: Заменён `pg_advisory_xact_lock` (не работал в autocommit режиме) на session-level `pg_advisory_lock`/`pg_advisory_unlock` для корректной блокировки при проверке лимита загрузок

#### Защита от несанкционированного доступа
- **Удаление чужих файлов**: Добавлена проверка `user_id` в `DELETE FROM temp_uploads` при удалении медиа - пользователь может удалить только свои файлы
- **Валидация URL медиа**: Добавлена проверка формата URL перед созданием поста - принимаются только пути внутри `/uploads/(videos|posts|gifs)/`

#### Проверка MIME типов
- Проверка MIME типов через `finfo_file()` уже реализована для всех типов медиа (изображения, GIF, видео)
- Предотвращает загрузку вредоносных файлов с поддельными расширениями

### Исправления

#### Критические баги
- **Комментарии с медиа не работали**: `Post::create()` пытался удалить медиа из `temp_uploads` для всех типов постов, включая комментарии. Теперь проверка выполняется только для основных постов (`$parentId === null`)
- **Синхронизация черновиков**: При публикации поста в одной вкладке, `localStorage` с черновиком не очищался в других вкладках. Добавлена обработка события `post_created` для очистки черновиков во всех вкладках

#### Восстановление медиа
- **Медиа возвращалось после удаления**: Восстановленные из `temp_uploads` медиа помечаются флагом `isRestored: true` и не синхронизируются с глобальным `UploadContext`, что предотвращает их возвращение после удаления
- **Удаление из контекста**: Добавлен вызов `removeUpload(id)` в `handleRemove` для удаления медиа из глобального контекста загрузки

### Логирование
- Добавлено подробное логирование в `deleteUploadedMedia()` для отладки проблем с удалением медиа
- Логи включают: проверку владельца, результат DELETE из БД, удаление файлов с диска

### 🔧 Технические улучшения
- Улучшена обработка ошибок при работе с `temp_uploads`
- Оптимизирована синхронизация медиа между вкладками через `BroadcastChannel`
- Добавлены блоки `finally` для гарантированного снятия advisory locks

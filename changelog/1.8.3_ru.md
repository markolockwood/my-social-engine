## [1.8.3] - 2026-04-09

### Функции

#### Система защищённых постов
Полноценная система приватности, позволяющая пользователям контролировать, кто может видеть их твиты, аналогично защищённым аккаунтам Twitter.

**Основной функционал**
- Пользователи могут включить "Защищённые посты" в настройках, чтобы сделать аккаунт приватным
- Защищённые аккаунты требуют подтверждения для новых подписчиков
- Только одобренные подписчики могут видеть посты защищённых аккаунтов
- Публичные пользователи видят сообщение, что посты защищены и нужно отправить запрос на подписку

**Процесс запроса на подписку**
- При подписке на защищённый аккаунт запрос переходит в состояние "ожидание" вместо автоматической подписки
- Владелец защищённого аккаунта получает уведомление и может одобрить/отклонить запрос
- Одобренные запросы преобразуются в обычные отношения подписчика
- Отклонённые запросы можно отправить повторно через 24 часа

**Визуальные индикаторы**
- Иконка замка (🔒) отображается рядом с именем защищённых аккаунтов по всему приложению
- Единообразное отображение во всех компонентах: посты, профили, карточки пользователей, всплывающие карточки, списки подписок
- Создан универсальный компонент `UserDisplayName` для единообразного вида

**Реализация на бэкенде**
- Используется новое поле `users.protected_posts`
- Класс `Post.php` обновлён для включения `protected_posts` во все запросы постов
- Эндпоинты запросов на подписку уже существовали, теперь интегрированы в UI

**Интеграция фронтенда**
- **Сайдбар**: Пункт меню "Запросы на подписку" с живым счётчиком в бейдже (обновляется каждые 30 сек)
  - Бейдж показывает количество ожидающих запросов (99+ если больше 99)
  - Виден только при наличии запросов
  - Ссылается на страницу `/follower-requests`
  
- **Списки подписок**: Добавлена вкладка "Запросы" на `/profile/{username}/requests`
  - Третья вкладка наряду с "Читатели" и "Читаемые"
  - Показывает ожидающие запросы с кнопками "Принять"/"Отклонить" прямо на странице
  - Бейдж на вкладке указывает количество запросов
  - Видна только для своего профиля при наличии запросов
  - Счётчик обновляется в реальном времени после действий
  
- **Карточки пользователей и профили**: Иконка замка рядом с именами защищённых пользователей
  - Реализовано через новый компонент `UserDisplayName`
  - Применяется в: Лента постов, цитируемые посты, карточки пользователей, всплывающие карточки, профили, списки подписок

**Улучшения UX**
- Быстрый доступ к запросам на подписку из сайдбара без навигации
- Управление запросами прямо на странице списков подписок для удобства
- Чёткое визуальное различие защищённых аккаунтов по всему приложению
- Видимость ожидающих запросов с первого взгляда через счётчики в бейджах

### Технические детали

**Паттерн компонента UserDisplayName**
```jsx
<UserDisplayName 
  displayName={user.display_name}
  isProtected={user.protected_posts}
/>
```
- Принимает `displayName` (строка) и `isProtected` (boolean)
- Рендерит имя с условной иконкой замка
- CSS: `display: inline-flex` с отступом 4px между именем и иконкой
- Прозрачность иконки: 0.7 для ненавязчивого вида
- В будущем может использоваться для новых значков рядом с именем пользователя

**Логика обновления бейджа**
- Интервал опроса: 30 секунд
- Загружается только счётчик, не полный список запросов
- Бейдж автоматически скрывается при достижении 0
- Счётчик ограничен 99+ для отображения

### Изменения базы данных

**Таблица users**
- Добавлено поле `protected_posts` BOOLEAN (по умолчанию: FALSE)
  - Контролирует, является ли аккаунт пользователя приватным
  - При TRUE требуется подтверждение запроса на подписку
  - Проиндексировано для производительности запросов
- Добавлено поле `privacy_settings` (json) для будущих настроек пользователя.

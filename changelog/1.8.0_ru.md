## [1.8.0] - 2026-08-08

### Новые возможности

#### Умный счётчик просмотров постов
- **Дедупликация просмотров по сессии** (аналог логики Twitter):
  - Повторный просмотр одного поста тем же пользователем не увеличивает счётчик в течение 3 часов
  - По истечении окна следующий просмотр снова засчитывается
  - Работает как для авторизованных пользователей (по ID), так и для анонимных (по IP)
  - Просмотр собственного поста автором засчитывается на общих основаниях
- **Учёт просмотров в ленте постов**:
  - Пост засчитывается как просмотренный, если провисел в зоне видимости (≥50% площади) не менее 3 секунд
  - Реализовано через `IntersectionObserver` в компоненте `Post`
  - Быстрый скролл не засчитывает просмотры мимолётно показанным постам
  - Просмотр в ленте и просмотр на детальной странице поста — это один и тот же засчитываемый эвент (не два разных просмотра)
- **Клиентская дедупликация запросов**:
  - Запрос на просмотр для конкретного поста отправляется не более одного раза за SPA-сессию
  - Повторное появление того же поста в ленте (после скролла вверх/вниз) не создаёт лишних сетевых запросов
  - Реализовано через `markPostViewed()` в `PostsContext`

### Backend

#### Интеграция Redis
- Добавлена зависимость **Redis** — используется для эфемерных данных (дедупликация просмотров, в будущем — presence/typing-индикаторы для чата)
- Новый класс `RedisClient` (`api/classes/Redis.php`) — singleton-обёртка над php-redis по аналогии с `Database.php`
- Новая секция `redis` в `config/config.php` (host, port, timeout)
- Деградация без сбоя: если Redis недоступен, просмотры считаются без дедупликации (не теряются), приложение продолжает работать

#### Изменения API
- `POST /api/posts/{id}/view` теперь возвращает `{ "counted": true|false }` вместо статичного сообщения — фронтенд использует это значение, чтобы понять, был ли просмотр реально засчитан
- Метод `RateLimitMiddleware::getClientIp()` сделан публичным для переиспользования в определении анонимных просмотров

### Исправления

#### Рассинхронизация счётчика просмотров
- **Исправлено**: при открытии поста счётчик показывал завышенное значение (+1) до прихода актуальных данных через polling `/counters`
- Причина: фронтенд оптимистично увеличивал счётчик без учёта результата дедупликации на сервере
- Теперь локальное увеличение счётчика происходит только при `counted: true` от сервера

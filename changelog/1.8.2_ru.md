## [1.8.2] - 2026-08-09

### Безопасность

#### Критические уязвимости устранены

**IP Spoofing в Rate Limiting**
- **Проблема**: Злоумышленник мог подделать заголовок `X-Forwarded-For` и обойти rate limiting, меняя IP при каждом запросе
- Добавлен whitelist доверенных прокси (localhost). X-Forwarded-For учитывается только от доверенного источника, с валидацией IP через `FILTER_VALIDATE_IP` и фильтрацией приватных адресов

**CSRF защита**
- **Проблема**: Отсутствовала защита от CSRF атак. Злоумышленник мог создавать посты, удалять контент от имени жертвы
- Создан `CsrfMiddleware` с проверкой Origin/Referer заголовков для всех POST/PUT/PATCH/DELETE запросов. Для запросов с JWT токеном проверка смягчена (JWT в localStorage уже защита от CSRF)

**Command Injection в FFmpeg**
- **Проблема**: Использование `exec()` со строкой команды создавало риск command injection
- Переписан метод `convertGifToMp4()` с использованием `proc_open()` и массива аргументов вместо строки. Хардкод пути к FFmpeg или строгая валидация из конфига. Добавлена валидация входных путей через `realpath()` для защиты от path traversal

**User Enumeration через error messages**
- **Проблема**: Детальные сообщения об ошибках (`"Username already exists"`, `"Email already exists"`) позволяли проверить существование username/email
- Обобщены сообщения об ошибках: `"Username or email already exists"` → `"Registration failed. Please try different credentials"`, `"Username is already taken"` → `"Username change failed"`

**Проверка файлов через Magic Bytes**
- **Проблема**: Проверка только MIME типа через `finfo_file()` без проверки реального содержимого файла
- Создан класс `FileValidator` с методами проверки magic bytes (первые байты файла) для JPEG/PNG/GIF/WebP. Добавлена проверка через `getimagesize()` и валидация магических сигнатур
- Проверка добавлена в `uploadPostImages()`, `uploadPostGif()`, `uploadAvatar()` - файлы с неверными magic bytes удаляются с сообщением "Invalid image file detected"

**Валидация gender с Whitelist**
- **Проблема**: Разрешен свободный ввод до 16 символов без проверки содержимого, возможность инъекций
- Добавлен whitelist разрешенных значений: Male, Female, Non-binary, Other, Prefer not to say. Пустое значение разрешено (опциональное поле)

**GeoIP через API**
- **Проблема**: Упрощенная проверка по префиксу IP (только для российских адресов), легко обойти
- Интегрирован бесплатный API ip-api.com (45 запросов/минуту). Добавлен таймаут 3 секунды, валидация IP с фильтрацией приватных адресов, graceful fallback при недоступности API

**Кроссплатформенное убийство FFmpeg процессов**
- **Проблема**: `pkill -f` работает только на Linux, на Windows не работает
- Решение: 
  - Добавлена миграция БД для хранения PID процесса в колонке `process_pid` таблицы `temp_uploads`
  - При запуске FFmpeg PID сохраняется в БД
  - Создан метод `killFFmpegProcess($pid)` с определением ОС (Windows: `taskkill /F /PID`, Linux: `kill -9`)
  - Обновлен `deleteMediaFile()` для использования PID вместо pkill
  - Fallback: если PID нет, использует старый метод

#### JWT secret: вынесен в .env
- Секрет теперь читается из `.env` (файл в `.gitignore`, не попадает в репозиторий)
- В README добавлена инструкция по генерации криптостойкого 256-битного секрета
- `config.php` подключает `.env` с фолбэком на placeholder, если `.env` не создан

#### CORS
- Заголовок `Access-Control-Allow-Origin: *` заменён на whitelist разрешённых origin'ов из конфига (`CORS_ALLOWED_ORIGINS` в `.env`)
- Автоматическое разрешение localhost-портов в development-режиме

#### Path traversal
- Эндпоинт `DELETE /upload/media` теперь валидирует пути через `realpath()`: итоговый путь обязан лежать внутри `/uploads`, иначе 403
- Проверка добавлена для одиночных файлов, директорий HLS-видео и превью

#### Access/Refresh Token система
Реализована стандартная схема с двумя токенами:
- **Access token** — 15 минут, передаётся в `Authorization` при каждом запросе
- **Refresh token** — 30 дней, хранится в БД `refresh_tokens`, привязан к user/IP/user-agent

**Преимущества:**
- Украденный access token бесполезен через 15 минут
- Refresh token можно отозвать через `logout-all`
- Обновление токена прозрачно через axios-интерцептор

**Файлы**: `api/classes/JWT.php`, `api/controllers/AuthController.php`, `src/context/AuthContext.jsx`, `src/api/api.js`, `database/migrations/013_add_refresh_tokens.sql`

### Рефакторинг

#### Устранение дублирования кода

**BaseController**
- Создан абстрактный `BaseController` с общими методами `getInput()`, `sendResponse()`, `sendError()`
- Все контроллеры теперь наследуются от базового класса: `class PostController extends BaseController`
- Удалены 6 дублированных методов (3 × getInput + 3 × sendResponse) из AuthController, UserController, PostController
- **Файлы**: `api/controllers/BaseController.php` (новый), все контроллеры

**TempUploadsHelper**
- Создан helper для работы с временными загрузками
- Методы: `checkLimitAndLock()`, `releaseLock()`, `register()`, `remove()`, `getAndRemove()`, `updateProcessPid()`
- Заменены 3 идентичных блока проверки лимита (~60 строк) в `uploadPostImages()`, `uploadPostGif()`, `uploadPostVideo()`
- Заменены 3 блока регистрации temp_uploads (~45 строк)
- Упрощены методы `cancelUpload()` и `deleteUploadedMedia()` через использование `getAndRemove()`
- **Файлы**: `api/helpers/TempUploadsHelper.php` (новый), `api/controllers/PostController.php`

**FileUploadConfig**
- Создана централизованная конфигурация для типов файлов
- Константы для MIME types, расширений, максимальных размеров для: изображений, GIF, видео, аватаров
- Методы: `getAllowedMimes()`, `getAllowedExtensions()`, `getMaxSize()`, `getUploadDir()`, `generateFilename()`
- Заменены hardcoded константы в 4 методах загрузки на централизованную конфигурацию
- **До**: `$allowedTypes = ['image/jpeg', 'image/png', 'image/webp']; $maxSize = 5 * 1024 * 1024;`
- **После**: `$allowedTypes = FileUploadConfig::getAllowedMimes('image'); $maxSize = FileUploadConfig::getMaxSize('image');`
- **Файлы**: `api/config/FileUploadConfig.php` (новый), контроллеры

**Реструктуризация фронтенд-компонентов по фичам**
- Компоненты перегруппированы по доменам:
  - `components/compose/` — ComposePost, ComposeWidget, ComposeReplyModal, MediaUpload

  - `components/user/` — UserCard, UserLink, UserHoverCard, EditProfileModal

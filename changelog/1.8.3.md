## [1.8.3] - 2026-08-20

### Features

#### Protected Posts System
A complete privacy system allowing users to control who can see their tweets, similar to Twitter's protected accounts.

**Core Functionality**
- Users can enable "Protected Posts" in settings to make their account private
- Protected accounts require approval for new followers
- Only approved followers can view posts from protected accounts
- Public users see a message that posts are protected and must request to follow

**Follow Request Flow**
- When following a protected account, request enters "pending" state instead of auto-following
- Protected user receives notification and can approve/decline the request
- Approved requests convert to normal follower relationship
- Declined requests can be re-submitted after 24 hours

**Visual Indicators**
- Lock icon (🔒) appears next to display name throughout the app for protected accounts
- Consistent display in all components: posts, profiles, user cards, hover cards, follow lists
- Created universal `UserDisplayName` component to ensure uniform appearance

**Backend Implementation**
- New `users.protected_posts` field utilized
- `Post.php` class updated to include `protected_posts` in all post queries
- Follow request endpoints already existed, now integrated into UI

**Frontend Integration**
- **Sidebar**: "Follower requests" menu item with live badge counter (updates every 30s)
  - Badge shows pending request count (99+ if more than 99)
  - Only visible when requests exist
  - Links to `/follower-requests` page
  
- **Follow Lists**: Added "Requests" tab on `/profile/{username}/requests`
  - Third tab alongside "Followers" and "Following"
  - Shows pending requests with inline Accept/Decline buttons
  - Badge on tab indicates request count
  - Only visible for own profile when requests exist
  - Real-time counter updates after actions
  
- **User Cards & Profiles**: Lock icon next to names of protected users
  - Implemented via new `UserDisplayName` component
  - Applied to: Post feed, quoted posts, user cards, hover cards, profiles, follow lists

**UX Improvements**
- Quick access to follower requests from sidebar without navigation
- In-page request management in follow lists for convenience
- Clear visual distinction of protected accounts across entire app
- At-a-glance visibility of pending requests via badge counters

### Technical Details

**UserDisplayName Component Pattern**
```jsx
<UserDisplayName 
  displayName={user.display_name}
  isProtected={user.protected_posts}
/>
```
- Accepts `displayName` (string) and `isProtected` (boolean)
- Renders name with conditional lock icon
- CSS: `display: inline-flex` with 4px gap between name and icon
- Icon opacity: 0.7 for subtle appearance
- Can be used for future badges next to user names

**Badge Update Logic**
- Polling interval: 30 seconds
- Only fetches count, not full request list
- Badge auto-hides when count reaches 0
- Counter clamped at 99+ for display

### Database Changes

**users table**
- Added `protected_posts` BOOLEAN field (default: FALSE)
  - Controls whether user's account is private
  - When TRUE, requires follow request approval
  - Indexed for query performance
- Added `privacy_settings` (json) field for future user settings
